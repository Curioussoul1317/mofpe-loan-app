# Loan Portfolio Management System
 
It is a small loan management system where users can manage customers, create loans, record repayments and view the remaining loan balance.

There are two user roles:

- Administrator
- Loan Officer

# Built With

- Laravel 13
- PHP 8.3
- MySQL 8
- Blade
- Bootstrap 5
- Laravel Sanctum
- PHPUnit
- Docker

# Features

The main features I implemented are:

- Login and logout
- Administrator and Loan Officer access
- Customer list and search
- Loan creation
- Repayment recording
- Multiple currencies
- Outstanding balance calculation
- Audit history
- Dashboard totals by currency
- REST API
- Swagger/OpenAPI documentation
- Automated tests

Loan numbers are generated automatically, for example: 
LN-000001
 

Repayment references are also generated automatically: 
PAY-000001
 

# Running the Project with Docker

Docker is the easiest way to run the project.

 bash
docker compose up
 

This will:

- start MySQL
- run the automated tests
- run the database migrations
- seed the database
- start the Laravel application

The application will be available at:
 
http://localhost:8000 

Swagger API documentation is available at:
 
http://localhost:8000/api-docs
 

To stop the containers:
 bash
docker compose down
 

To remove the database volume and start again from a fresh database:

 bash
docker compose down -v

# Running Without Docker

If Docker is not used, install the PHP dependencies:

 bash
composer install
 

Create the environment file:

 bash
cp .env.example .env
 

Generate the Laravel application key:

 bash
php artisan key:generate
 

Update the database settings inside `.env`.

Then run:

 bash
php artisan migrate --seed
php artisan serve
 

# Some Design Decisions

For money values I used:

 
DECIMAL(28,8)
 

instead of float/double because financial values should not lose precision.

BCMath is used for money calculations.

Each currency also stores the number of decimal places it supports. For example, USD and MVR currently use 2 decimal places.

I did not store the outstanding balance as a separate column. It is calculated from:
 
Principal - Total Repayments
 

This avoids having a stored balance that could become different from the repayment records.

When a repayment is recorded, it is done inside a database transaction.

The loan row is also locked using:

 php
lockForUpdate()
 

before checking the outstanding balance. This is to prevent two repayments being processed at the same time and causing the loan to be overpaid.

A repayment must use the same currency as the loan. I did not add currency conversion because it was outside the assignment scope.

Loan creation, loan updates and repayments are also recorded in the audit table.

Loan numbers and repayment reference numbers are generated by the system instead of being manually entered.

Loan editing is kept limited because changing the principal or currency after repayments have already been made could make the financial history inconsistent.
